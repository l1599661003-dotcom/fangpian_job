# 简历解析质量保护

本轮只调整解析、复核提示及重新识别链路，不迁移或批量重写存量人才数据，不主动触发评分、岗位匹配或群推送。

## 已覆盖的故障及处理

| 风险 | 处理 | 回归测试 |
| --- | --- | --- |
| 将“7年工作经验”误当成分区标题 | 按独立标题或带冒号的标题定位 | resume-sections |
| 标题带空格、编号、括号、英文，跨页重复标题 | 支持常见变体，汇总同类分区 | resume-quality |
| 长工作经历超过2000字 | 不截断规则分区 | resume-sections |
| 工作、项目、教育和技能串区 | 独立分区边界；明确分区优先于AI摘要 | resume-sections |
| 正序排列取错最近公司，或把学校当公司 | 只在工作/实习区取值，优先至今及最新开始日期 | resume-quality |
| PDF文本层日期与画面不一致 | 日期页转PNG，经平台OCR对照；不同则提示复核，不能擅自认定某一方正确 | resume-quality |
| 部分页是扫描页，或同页文字和大图混排 | 逐页识别；较完整的整页OCR补充图片正文并提示复核 | resume-quality |
| OCR只读到第一页、扫描页失败 | 明确读取总页数；逐页处理；必要页失败则整份失败，不保存残缺内容 | resume-quality |
| 附加空白页导致整份失败 | 对无文本无大图页检查实际灰度画面，确认空白才跳过；全空白文件拒绝入库 | resume-quality |
| 画面校验暂时不可用 | 已有可读文本可保留，但持久化“校验失败”提示；不是声称校验通过 | resume-quality |
| 水印和乱码 | 保留已有BOSS已知水印规则；低质量文字不直接认定成功 | resume-pdf-watermark / resume-quality |
| 英文PDF误判为扫描件 | 不以“必须含中文”判断文字有效性 | resume-quality |
| TXT为UTF16或GB18030 | 按BOM/严格解码识别；GB18030回退有提示；不可读内容报错 | resume-quality |
| Word表格或数字XML实体丢失分隔 | 保留单元格边界，解码数字实体 | resume-office-extraction |
| Word含图片简历但仅提取少量正文 | 转PDF后逐页处理；转换失败明确报错，不假装完整 | resume-quality |
| 并发Office转换互相抢用户配置 | 每个临时目录使用独立LibreOffice配置 | 代码边界检查 |
| OCR返回MCP外层结构或错误对象 | 拆包后校验文本；不能把对象或错误消息保存成简历 | resume-quality |
| AI电话、邮箱、日期、公司、年龄或性别缺乏原文证据 | 联系方式按原文；年龄性别只认明确表述；无法验证的公司/日期回退并提示 | resume-quality |
| 工作年限矛盾、多个手机号、时间倒置、双栏排版 | 生成待复核提示，不猜测或自行改写 | resume-quality |
| 手机号带空格/短横线或被隐藏 | 支持完整号码格式；不补全星号隐藏号码 | resume-quality |
| AI超时、JSON异常或长文截断 | 规则兜底，保留完整原文，并明确提示AI提取失败/长度限制 | resume-sections / resume-quality |
| 相同原件重新识别后新建档案、改招聘流程 | 更新原解析记录，不调用入库评分链路；非当前版本不覆盖当前候选人 | resume-quality |
| 自动解析覆盖人工修正 | 已修正/确认的现有字段优先，包括人工清空的值 | resume-quality |
| 下载超大文件或永远不返回 | 30秒下载超时；同时检查响应头及实际累计字节；10MB上限 | resume-quality |
| 批量OCR超时后仍继续后续入库 | 超时发出取消信号；分页面及进入写入/人才处理前检查取消 | resume-quality |

## 用户可见性与存储

- 固定表 `resume_extraction_records` 新增长文本字段 `解析质量JSON`，由现有数据库初始化机制补齐，写入前仍检查字段。
- 简历解析详情、人才档案详情均显示“解析结果有待核对项”；原始文件和人工复核入口仍保留。
- 提示不是认定候选人有问题，也不是自动淘汰/录用结论。
- 已人工复核的提示标记为“解析提示 · 已人工复核”，不删除历史检测事实。
- 存量档案没有该字段时按空提示处理，本轮不自动批量回填。

## 边界和后续人工验收

- 不能承诺所有模板100%正确。手写、严重模糊、特殊字体、复杂多栏排版、同一文件包含多人简历，仍需对照原件人工复核。
- 当前按页核验的是日期及明显缺失的扫描正文，不是所有字词都进行双引擎一致性比对。OCR本身也可能看错，因此日期冲突不自动改写。
- 日期画面校验会增加OCR调用和耗时；普通可读无日期、无大图PDF页直接使用文本层。每次OCR45秒超时，逐页执行；30页以上拒绝静默截断并要求拆分。
- 因源文档缺失而未识别字段，与“候选人没有相关经历”是不同含义。
- 已发出的数据库请求/外部调用不具备跨服务事务撤销能力；取消检查阻止后续处理，不能声称已在途请求全部回滚。
- 本地自动化使用模拟OCR/存储返回及真实PDF渲染。真实平台OCR、数据库新增字段和页面交互需在Studio重建后验收。
