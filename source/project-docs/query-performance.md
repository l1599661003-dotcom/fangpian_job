## 2026-09-29

本次仅优化读取路径和加载时机；不删除简历、附件、历史记录，不修改流程状态或角色权限。

| 页面/公共链路 | 已落地调整 |
| --- | --- |
| 人才档案 | 总数查询与首屏查询同时启动，不阻塞关联数据加载；头像自动补齐仅读取头像关联字段，不扫描完整 OCR 和履历内容 |
| 首页 | 简历、人才、应聘、面试、Offer 统计使用明确字段投影；月度需求在数据库按月过滤；保留原统计口径和部门权限 |
| 岗位库/岗位选项 | 岗位下拉复用已有短时原始数据缓存，仍逐请求应用部门权限；延续已有轻量岗位列表和编辑时加载员工选项 |
| 题库 | 题目与反哺任务并行查询；反哺仅查授权岗位的入职记录及其关联评价、离职记录；无授权岗位不扫描生命周期表 |
| 内部推荐 | 候选人、应聘、岗位关联仅读取展示字段；活动数据和其余关联表并行读取；保留推荐人可见范围 |
| 面试 | 按权限、日期、状态先筛选，再批量读取涉及候选人的姓名和岗位；不再为日历读取完整人才库 |
| Offer | 历史首屏仅请求 Offer；模板在模板管理/填写时加载；候选人与岗位在填写时加载；定向填写只获取绑定候选人；后端列表不初始化模板，关联候选人按 ID 查询 |
| 定时任务 | 配置和执行历史并行查询，数据库按 StartedAt 降序读取最新 50 条，不先拉历史大集合再截取 |
| 开发者中心 | 接口说明立即显示，API 配置独立加载；配置失败保留说明和重试；现有 API 配置只读取一次，保留原密钥 |
| 登录权限 | 成功通过权限守卫后，以当前 HTTP headers 对象为弱引用键，在同一请求内复用身份/权限结果；新请求仍检查会话和账号，未引入跨请求登录缓存 |
| 数据分页 | 识别代理返回页大小后自适应，避免每页重复探测；关联 ID 分批查询并完整分页，避免单页截断 |

## 验证与测量边界

- 所有新增字段投影均与真实 Teable 字段定义核对；开发期只读，不发送消息或更改业务数据。
- 真实 Teable 工具抽样，同一批 25 条记录：简历完整字段 278117 字符，首页统计投影 5151 字符；候选人完整字段 58813 字符，姓名/邮箱关联投影 4822 字符。
- 上述为序列化记录的字符数，不是网络压缩后的字节数，也不是整页提速百分比；单次工具耗时不能替代发布环境端到端测量。
- 回归覆盖首页统计、面试可见范围、Offer 延迟加载、请求内权限复用、新请求账号停用、1000 条分页、关联查询不截断、最新任务历史、开发者配置失败重试。
- 尚不能承诺所有线上页面低于 1 秒。发布后应按实际账号分别测冷请求和重复请求，记录浏览器 Network 的接口等待/响应大小，以及首次可操作时间。
- 人才复杂组合筛选仍需汇总关联摘要；首页仍需读取跨流程统计摘要。若这两条路径在线上仍超目标，应以真实耗时继续细分，而非删除附件或跳过权限检查。

## 缓存与再次打开优化

新增 `server/platform/read-cache.ts`，由服务显式声明依赖表，不对所有数据库查询盲目缓存。

| 读取路径 | 缓存策略 |
| --- | --- |
| 人才列表/统计/员工摘要 | 60 秒，最多 24 个条目；筛选、页码作为不同键；权限与脱敏仍逐请求执行 |
| 人才详情 | 30 秒，最多 8 份原始关联数据；每次重新执行当前用户权限检查与敏感字段解锁判断 |
| 浏览器人才列表 | 内存中保留最近 8 组结果，30 秒内返回列表可先显示旧结果，但每次仍向服务器校验更新；不写 localStorage/磁盘 |
| 首页 | 30 秒，最多 25 个按月份和部门范围区分的结果，合并并发查询 |
| 题库 | 题目原始记录 30 秒，按当前用户和岗位重新过滤；题库完善任务按授权岗位集合缓存 15 秒 |
| 面试/内部推荐 | 沿用已有短时 TTL，增加依赖表失效和并发合并；面试日历的关联候选人摘要缓存 30 秒 |
| Offer 列表 | 按状态、候选人条件缓存 30 秒；详情操作仍走原流程 |
| 定时任务 | 配置与最近运行记录缓存 5 秒，更新/执行结果写入后失效 |
| 数据分析 | 汇总结果缓存 30 秒；同一授权筛选下的数据集缓存 15 秒，汇总与下钻共享，避免每次下钻重新读取 19 张表 |
| 岗位、开发者配置 | 保持已验证的岗位查询路径与现有配置缓存，不改密钥或岗位功能 |

缓存规则：

- Teable SDK 写入开始和结束时都更新该表的本进程版本号；依赖该表的缓存下次读取不再命中。失败的写入同样失效，避免不确定提交结果被旧缓存掩盖。
- 待完成读取会合并，不会因加载时间超过 TTL 而重复启动；TTL 从读取成功后计算。失败不缓存，旧请求不能删除或覆盖新的缓存条目。
- 返回值克隆，防止调用者修改、排序返回数据而污染其他用户/请求；条目数量有上限。
- 列表手动刷新携带 `refresh=1`，绕过人才缓存；浏览器写操作、后台任务结束、退出登录、账号/权限刷新会清理人才结果快照。
- 401/403 立即移除浏览器缓存卡片，不回退读取历史简历；普通网络故障可以明确标注显示上次结果，并支持重试。
- 不缓存登录会话、账号启用状态或临时敏感授权的判断结果。已有全字段权限的人才列表不再额外查询不能增加权限的解锁记录。

部署边界：缓存是有界进程内缓存，并非 Redis 或跨副本消息总线。通过另一个应用进程、另一个环境或 Teable 界面写入的数据，仍依靠短 TTL 或手动刷新同步；不承诺跨副本瞬时失效。冷启动/第一次查询仍需要数据库访问。

新增确定性验证：1000 人列表同条件再次读取不增加业务表查询；数据写入后重新读取、显式刷新、详情按不同用户重新脱敏、过期/失败重试、并发写读竞态、LRU 上限、浏览器先显示缓存再更新、403 清空旧卡片，以及分析汇总/下钻共用 19 表数据集。

### 首次计数与重复渲染

- 已从真实工具清单验证 `teable_get_table_row_count`，并通过只读调用核对 `row_count` 响应。应用通过现有平台 MCP 桥调用，不自造接口。
- 人才无搜索条件的总数使用“数据库聚合总数减去已删除/已合并数量”，只分页查询排除记录的摘要。带搜索/状态/来源条件的计数仍走准确过滤摘要，未给不支持筛选的聚合工具传入虚构参数。
- 聚合失败或计数不一致时回退原有摘要计数，不把失败当成零条记录。一次真实只读核对中，总记录为 1176、排除记录为 103；这是当时的数据快照，不代表固定业务数量或页面端到端耗时。
- 人才后台校验结果未变化时跳过整页 DOM 重绘；新增浏览器测试确认卡片节点保留，避免反复重绘导致闪动及丢失浏览位置。
