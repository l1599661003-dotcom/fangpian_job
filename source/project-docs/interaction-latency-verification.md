# 人才档案与面试操作等待优化

## 修改范围

- 人才列表并行读取目录、员工状态和岗位权限；档案主记录与关联数据并行读取，历史简历和应聘记录的兼容关联保留。
- 同一人才详情的前端进行中请求合并；从已打开档案进入定向邀约复用已有资料，保存时仍由后端验证。
- 敏感字段授权查询按当前申请人过滤，授权有效期与候选人范围检查不变。
- 调整面试时段采用 450ms 防抖；同一时段合并进行中的会议室请求，旧时段响应不能覆盖新时段。
- 安排面试查询使用 source=wecom，通过天玑 `freeMeetingRooms` 按面试开始、结束时间查询，不再调用旧的 `wecom meeting rooms search`，也不要求用户输入会议室名称关键词。
- 查询窗口前后扩展 24 小时，以覆盖上游可能漏报的跨边界预约；随后按每条预约的实际开始/结束时间与面试时段做区间重叠判断。空闲列表若带重叠预约仍标为占用；占用项缺少明细时按不可预约处理。
- 查询结果在面试选择中完整呈现空闲与占用会议室；只有确认空闲的会议室可选。提交时重新请求天玑并复核时间冲突，企微日历创建仍使用原有流程。
- 查询结果附带服务端选择标识，绑定时段与会议室，15 分钟内有效；改时间、伪造会议室或服务重启后必须重新查询。查询本身不写数据库。
- 创建时验证该选择标识，仅保存选中会议室的必要关联，兼容后续改期、取消和历史展示；服务端再次查询天玑并复核会议室与本地排期，之后仍由企微日历回执确认日程创建结果。
- 下拉选项携带面试官企微 ID，提交时与服务端可用面试官核对。创建日程复用这次核对后的 ID，不再重复解析人员目录；旧客户端未传企微 ID 时仍兼容。
- 旧预约的管理、改期与重试入口保留原有本地会议室映射和校验逻辑。
- 日程、邮件和会议室查询支持后台任务，前端显示进度。原同步接口保留，不带 background=true 的调用行为不变。
- 同一创建请求标识返回同一后台任务；轮询断网后再次查看结果不会重新提交。
- 会议室查询走工作区配置的天玑接口，日历创建、修改和取消仍使用企微日历连接器；查询失败不显示为已成功同步。
- 保存面试和同步会议室后清理面试模块缓存，避免立即返回列表时仍显示旧结果。

## 验证

- Teable 的面试开始、结束时间字段不能使用大小比较筛选。时段检查采用分页读取后在应用端解析时间，保留跨页记录、时区换算和相邻时段不冲突的语义；不缓存冲突判断。
- 新增回归用例模拟文本时间字段拒绝比较运算，覆盖第二页预约、首尾相接时段、时区偏移及新增预约立即可见。此前忽略筛选参数的替身不能发现这类真实平台兼容问题。

- interaction-latency.test.mjs：档案并行读取、后台任务立即返回、同提交去重、同步接口兼容、指定会议室查询范围。
- ui-regression.spec.mjs：连续调整时间的请求合并、旧响应丢弃、任务轮询中断后的恢复、定向邀请和成功/部分失败回执。
- integration-boundaries.test.mjs：直接会议室查询零数据库读取、创建不重复搜索、人员 ID 不一致拒绝、时段或选择失效拒绝、保存关联后的重试同步和取消。
- 手机端新增验证：不请求本地会议室、提交接口带选中会议室与面试官企微 ID、提交不再查询、修改时间清除旧选择。
- 原招聘、面试、权限与 Offer 测试继续验证现有业务链路。
- 测试使用模拟数据库和外部服务，不占用真实会议室，不向候选人或 HR 发送测试邮件。

## 验收边界

- 后台任务与提交标识沿用当前进程内任务机制，不是跨重启持久队列。服务重启、页面刷新或关闭后，应先在面试排期核实记录，不能把丢失任务当作未创建。
- 外部平台本身的耗时仍然存在；本次减少串行和重复查询，并避免长请求一直等待响应头，不承诺所有操作秒完成。
- 本地构建与模拟回归不等于发布或真实企微验收。平台更新预览后需验证真实页面等待、日程回执和邮件结果。
