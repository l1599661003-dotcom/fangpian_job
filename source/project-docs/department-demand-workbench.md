# 每日需求提醒的部门工作台

- 保留既有 `flow_action=demand&demand_month=YYYY-MM` 链接，登录后先打开部门工作台，不再自动选择第一条岗位填表。
- 服务端按可信登录用户 ID 查询员工部门，结合原岗位数据权限。管理员从此入口进入也默认限定本人部门；无部门绑定或权限时明确提示，不退回全公司岗位。组织下级部门仍须在当前授权范围内。
- 默认展示在招岗位，可切换已暂停、全部部门岗位。支持切换月份、查看业务负责人及招聘 HR、本月需求和审批状态、累计应聘／接受 Offer／到岗人数；累计指标不是本月达成率。
- 新增、调整及 AI 解析复用原需求流程，服务端重新核验部门。一个岗位一个月份仍是一条需求，数量为该月总人数，不是追加人数；保留既有审批及通知机制。
- 暂停沿用岗位级“已下线／暂停招聘”，需要原因、有权限才可操作，保留需求及候选人，不取消已有面试。不是仅暂停某个月份的需求；重新新增或调整有效需求仍沿用原自动开放岗位机制。
- 部门工作台接口使用 `create_demand` 写权限；暂停属于需求管理动作，不开放其他岗位配置权限。暂停重试幂等，失败保留原因，成功刷新工作台。
- 本轮通过模拟数据验证，不发送真实群提醒，不创建或暂停真实招聘需求。预览、真实企微登录身份及生产发布验收需分别确认。
