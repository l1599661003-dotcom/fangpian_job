# 面试与企微会议室双向同步方案

## 1. 目标

让招聘同事只维护一次面试安排，会议室占用状态在招聘系统和企业微信（以下简称“企微”）之间保持一致，并支持两种入口：

1. 招聘系统创建、改期或取消面试时，自动在企微预定、变更或释放会议室。
2. 行政/招聘同事先在企微预定会议室时，系统自动在招聘系统生成或更新对应的“面试场地安排”。

适用资源包括普通面试会议室、拍摄间，以及按楼层、容量、电视、白板等设备区分的会议室。

## 2. 推荐原则：一套主数据、双向事件同步

不建议简单地将两套系统“互相覆盖”。建议按数据对象划分主责：

| 数据对象 | 主数据系统 | 说明 |
| --- | --- | --- |
| 候选人、岗位、面试官、面试轮次、面试结论 | 招聘系统 | 企微不应保存或展示候选人敏感信息。 |
| 会议室目录、楼层、容量、设备、实时占用状态 | 企微 | 招聘系统仅保存必要的映射和缓存。 |
| 与面试关联的预约记录 | 招聘系统 | 每条记录保存企微预约 ID，便于幂等更新和追溯。 |

核心原则：**谁先成功锁定企微会议室，谁才算预约成功。** 招聘系统发起时，要以企微的创建结果为准；企微侧发起时，要以企微的预约事件为准。

## 3. 业务流程

### 3.1 在招聘系统预定（主路径）

1. 招聘同事填写候选人、面试轮次、时间、时长、面试形式、人数、面试官和场地需求。
2. 招聘系统按时间、容量、楼层、设备筛选并展示企微可用会议室；默认推荐最合适的一个。
3. 用户确认后，招聘系统向企微创建会议室预约。
4. 企微返回成功和预约 ID 后，招聘系统将面试状态更新为“已安排”，写入会议室名称、企微预约 ID、同步时间和版本号。
5. 若企微返回冲突，招聘系统提示“该会议室刚被占用”，刷新可选房间；不得仅在招聘系统内标记成功。

建议预约名称使用脱敏格式，例如：`面试｜产品经理｜14:00-15:00`。不要在企微会议标题中直接放候选人姓名、手机号、简历链接或面试评价。

### 3.2 在企微预定后回写招聘系统

1. 企微产生会议室预约创建、变更或取消事件；对接服务接收回调或按固定频率拉取增量记录。
2. 服务根据预约标题中的标准标识、预约人、时间和会议室，匹配招聘系统中的待安排/已安排面试。
3. 匹配成功：更新对应面试的场地、时间、企微预约 ID 和同步状态。
4. 无法自动匹配：生成“待关联会议室预约”任务，由招聘运营人员选择对应候选人/面试轮次后确认。
5. 非面试用途预约不写入招聘系统。

为提高匹配率，建议企微预定时使用统一标题规则：

`【面试】岗位简称｜面试轮次｜招聘系统面试编号`

其中“招聘系统面试编号”是唯一键。例如：`【面试】产品经理｜一面｜INT-20260816-00128`。系统只需识别这个编号即可关联，避免用姓名匹配造成误关联和隐私暴露。

### 3.3 改期、换会议室与取消

| 操作入口 | 同步动作 | 成功标准 |
| --- | --- | --- |
| 招聘系统改期 | 先在企微变更/重新创建预约，再回写招聘系统 | 新时段在企微锁定成功，旧时段已释放。 |
| 招聘系统换房 | 在企微确认目标房间成功后，再释放旧房间 | 不出现面试无会议室的中间状态。 |
| 招聘系统取消 | 取消企微预约并标记面试场地已释放 | 企微资源释放成功或进入待重试。 |
| 企微改期/换房 | 回写对应面试；若影响面试官日程，触发提醒 | 招聘系统展示企微最新安排。 |
| 企微取消 | 招聘系统保留面试记录，但标记“场地待重新安排” | 不自动取消候选人面试。 |

## 4. 功能需求

### 4.1 招聘系统页面

- 面试创建页新增“会议室安排”区域：日期、起止时间、时长、地点/楼层、人数、设备需求、会议室。
- 支持按容量、设备（电视、白板等）、楼层、是否拍摄间筛选。
- 展示企微实时可用状态和最近一次刷新时间。
- 支持“自动推荐”“手动选择”“暂不安排会议室”。
- 在面试详情页展示同步状态：已同步、同步中、冲突、待关联、失败待重试。
- 提供“重新同步”“查看同步记录”操作；普通招聘人员只可重试自己有权限的面试。

### 4.2 同步任务与运营后台

- 接收或拉取企微的创建、更新、取消、会议室状态变化。
- 失败自动重试：建议 1 分钟、5 分钟、15 分钟、1 小时递增，最多 5 次。
- 超过重试次数后创建待办并通知招聘运营/系统管理员。
- 提供异常队列：重复预约、无法匹配、房间已被占用、权限不足、接口不可用。
- 提供按面试编号、企微预约 ID、会议室、日期查询的审计日志。

## 5. 对接设计

### 5.1 适配层

建立一个“会议室同步服务”，屏蔽企微侧具体实现。招聘系统只调用统一能力：

| 统一能力 | 用途 |
| --- | --- |
| 查询会议室目录 | 同步楼层、容量、设备和启停状态。 |
| 查询可用时段 | 招聘系统展示候选会议室。 |
| 创建预约 | 面试确认时占用会议室。 |
| 修改预约 | 改期、换房、变更预约人。 |
| 取消预约 | 面试取消或释放场地。 |
| 获取预约增量 | 处理企微侧手动预定/变更。 |
| 接收事件 | 有条件时优先使用回调，提高实时性。 |

企微侧实现优先级：

1. 贵司已开通的企微官方能力或会议室服务商接口。
2. 企业内部应用通过授权调用相关能力。
3. 无接口或无回调时，定时导出/增量拉取预约数据。
4. 以上均不可用时，以 RPA 自动操作企微后台作为临时方案；RPA 需有运行监控、截图留痕和人工兜底，不建议作为长期核心链路。

上线前需由企微管理员确认：可调用的能力、应用权限、可访问的会议室范围、预约创建人规则、回调/增量数据获取方式及频率。

### 5.2 关键数据字段

| 招聘系统字段 | 企微字段/含义 | 说明 |
| --- | --- | --- |
| interview_id | 预约标题中的唯一标识 | 双向关联的主键。 |
| room_booking_id | 企微预约 ID | 防止重复创建，支持精确修改/取消。 |
| room_id | 会议室 ID | 不以名称作为唯一键。 |
| start_at / end_at | 预约起止时间 | 统一使用北京时间与 ISO 8601 存储。 |
| organizer_id | 预约发起人 | 用于权限校验和异常定位。 |
| sync_source | ATS / WECHAT_WORK | 标识最后一次有效变更来源。 |
| version / updated_at | 版本或更新时间 | 解决并发更新。 |
| sync_status / error_message | 同步结果 | 便于前台展示和运营处理。 |

## 6. 冲突与一致性规则

1. **并发抢占**：展示“可用”不等于可预定。最终以企微创建预约成功为准。
2. **同一预约重复投递**：以 `room_booking_id + 事件版本` 或幂等键去重，重复消息不重复建单。
3. **双方同时修改**：优先采用乐观锁；如无法获取版本号，则以企微最后更新时间为场地事实来源，同时保留冲突记录给人工确认。
4. **招聘系统改期失败**：保留原预约，不更新招聘系统的确认时间；前台明确提示未成功改期。
5. **企微取消会议室**：只将招聘系统标记为“场地待重新安排”，不自动取消候选人和面试官日程。
6. **网络/接口故障**：进入“同步中/待重试”，不要把未确认的房间写成已预定。
7. **手工预约无编号**：进入待关联队列，禁止系统按候选人姓名自动猜测关联。

## 7. 权限与隐私

- 同步服务使用专用企业应用身份，不使用个人账号长期运行。
- 按最小权限原则仅授予可管理的会议室和必要的预约读写权限。
- 企微预约标题、通知和日志中禁止存候选人简历、联系方式、身份证件、面试评价等敏感信息。
- 招聘系统内保留完整候选信息；企微只展示岗位简称、轮次、时间和必要组织者信息。
- 所有创建、变更、取消和人工关联均记录操作人、来源、时间和前后值。

## 8. 分期落地建议

### 第一期：招聘系统 → 企微

- 同步会议室目录、可用性查询、创建/取消预约。
- 支持常规面试预定、冲突提示、失败重试和审计日志。
- 面试改期可先采用“取消旧预约 + 创建新预约”的可控方式。

### 第二期：企微 → 招聘系统

- 接入回调或增量同步。
- 使用标准预约标题自动关联面试编号。
- 建立待关联队列和运营处理闭环。

### 第三期：体验优化

- 智能推荐会议室（按人数、设备、楼层、相邻面试连续排布）。
- 候补房间、自动释放未签到预约、面试官日历协同。
- 数据看板：会议室利用率、冲突率、临时取消率、同步成功率。

## 9. 验收标准

1. 招聘系统预定会议室后，在约定时效内（建议 30 秒内）可在企微看到对应预约。
2. 企微侧创建、改期、换房、取消的面试预约，能够在约定时效内回写招聘系统；无法匹配的记录进入待处理队列。
3. 同一面试重复点击提交或重复接收事件，不会产生重复会议室预约。
4. 发生冲突时，任何一端都不显示“已成功预定”的错误结果。
5. 改期或换房失败时，原会议室预约保持有效且可追溯。
6. 企微端不展示候选人敏感信息；管理员可查询完整同步日志与失败原因。

## 10. 需与企微管理员确认的清单

1. 当前会议室预定模块的具体产品形态：企微原生、第三方应用或自建应用。
2. 是否能获得会议室目录、空闲时段、创建/修改/取消预约、预约增量或事件回调能力。
3. 可授权的企业应用、测试企业/测试会议室及接口调用频率限制。
4. 是否允许以专用服务账号创建预约；若不允许，预约应归属招聘专员还是面试组织者。
5. 会议室预约可写入的标题、参与人、备注字段以及对外可见范围。
6. 现有企微预约中，怎样识别“面试预约”并推动统一标题规范。
