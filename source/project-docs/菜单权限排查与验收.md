# 菜单权限排查与验收

更新日期：2026-09-28

## 配置原则

- 普通员工只需内部推荐时，启用的角色应只授予 `referrals` 页面。手机直接显示内部推荐入口，电脑不显示首页、岗位、人才档案、面试等未授权菜单。
- 角色授权是追加，不是替换。多个有效角色的页面和操作权限取并集；有 HRBP 或管理员等角色时，修改普通员工角色不会收回其他角色的权限。先核对员工绑定，确认后再移除不需要的角色，不要批量删除合法 HR 授权。
- 菜单权限与操作权限分别校验。页面隐藏不是安全边界；后台接口仍要求可信身份、启用账号、页面权限和对应操作权限。
- 员工登录会话优先于平台身份头。过期、退出或格式无效的会话不能回退到平台管理员身份；停用账号不能继续访问业务接口。
- 修改角色权限、追加或撤销角色会清除当前进程权限缓存。其他实例保留最多 60 秒缓存；已打开页面会在重新聚焦、重新可见、权限错误或可见状态下每 60 秒检查权限。若检查失败则阻止继续使用，提供重新检查入口。
- 普通员工的内推列表、活动和统计在后端限定本人；创建个人海报时推荐人来自可信账号，不能使用提交参数冒充他人。奖励发放与内推审核不能仅凭个人内推权限操作。
- 私有后台任务结果必须属于发起人，并仍具备原页面和操作权限。匿名内推上传只允许凭其随机任务 ID 查询该次提交；不开放其他系统或员工任务。

## 发布后人工验收

1. 使用仅绑定普通员工角色的测试账号登录，确认 `/api/access/me` 的用户与本人一致，页面列表只有 `referrals`。
2. 手机和电脑仅显示内部推荐；直接打开面试邀请管理等内部深链接不能打开未授权弹窗。
3. 使用该会话请求人才、岗位、面试、Offer、题库、开发者中心、定时任务、分析、权限管理接口，确认返回拒绝访问。
4. 保持员工页面打开，由管理员收回权限，再切回员工页面，确认菜单与已打开业务弹窗被更新或关闭。
5. 检查本人内推海报、提交和进度查询仍可用；换另一名员工确认不能看到前一人的内推记录。
6. 使用合法 HR / 管理员账号复核原有业务功能。公开候选人链接仍沿用各自的令牌校验，不能用菜单权限代替公开链接的令牌校验。

本地浏览器测试使用接口模拟数据，不等同于生产账号验收或已发布。不要为测试向真实群发消息、创建真实会议或修改真实员工角色。
