# 长耗时操作与超时处理

## 本轮覆盖

- 意向沟通、面试评价、公开面试总结、月度招聘需求、部门需求的 AI 解析：前端请求后台任务，轮询结果后填表；保留旧同步 API 契约。
- 需求保存/暂停/审批、沟通保存、人才评审/阶段推进/群推送、面试评价/决策/记录保存、公开沟通/评价提交、企微资源同步及面试邮件操作、Offer 创建/审批/文件生成/邮件发送等：前端通过白名单启用后台操作。
- 会议室查询、面试创建、面试题生成、测评题目草稿、面试纪要、简历解析、首次人才分析和定时任务：使用统一后台等待策略。其他原有任务的 GET 查询也支持短暂网络故障重试。
- 外部 LLM 请求默认 120 秒中止；支持单次调用指定上限。MCP 单次请求 180 秒，工具清单请求 30 秒。它们仍通过平台 SDK 桥接，不直接访问连接器。

## 关键契约

`BackgroundActionsInterceptor` 只接受明确列举的 POST JSON 操作，必须携带 `x-background-action` 随机请求标识。正常查询、文件下载、没有该标识的旧调用方保持原契约，不会被统一包装。

拦截器运行在权限守卫之后、审计拦截器之前。原控制器的身份/Token/数据权限校验仍执行；数据脱敏和业务成功/失败审计在后台操作完成时执行。内部任务绑定发起用户及原权限，公开表单任务使用不可猜测的随机任务 ID，原 Token 校验不会跳过。

同一进程内按用户、路由、查询参数、请求体和请求标识散列去重。前端保留当前页面中未确认的请求标识及任务 ID：启动回执丢失时重用标识，轮询故障时只查询原任务，不重新发起写入。不同用户/不同内容不会错误合并。

轮询失败不等于业务失败。400/401/403/404 不自动反复查询；临时网络故障最多连续重查 3 次。AI 填表最多等待 4 分钟，一般后台任务等待 10 分钟；超出页面等待时间不会取消已经开始的后台写入，也不会自动重放操作。

## 边界

- 无法保证第三方服务永不超时。界面必须区分“仍在处理/结果未确认”和“已成功/已失败”，不能把超时当成已保存，也不能因此盲目重发通知。
- 任务和请求去重仍使用现有内存任务注册表，不是持久化队列。服务重启会丢失任务查询状态，页面刷新会丢失前端待查询映射；遇到任务过期应先核实业务记录再决定是否重试。
- 一个业务操作可能包含多个 Teable 写入及外部发送，不是数据库事务；已失败任务可能仍有部分成功步骤，不应宣称自动回滚或跨服务“恰好一次”。
- 后台任务不替代人工确认：AI 解析仅填写草稿，不自动提交录用判断。
- 本轮自动化验证使用替身服务，不向真实候选人、HR 或企业群发测试通知。实际第三方授权与送达需在平台运行环境验收。
