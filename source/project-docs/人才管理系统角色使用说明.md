# 方片人才管理系统角色使用说明

更新日期：2026-08-28

## 1. 系统业务主线

系统围绕一条统一人才生命周期工作：

> 收简历 → 负责人审查 → 意向沟通 → 约面 → 面试 → Offer / 答复 → 背调 → 入职 → 离职 → 回访

所有角色应在系统中推进阶段、填写原因和保存业务证据，不以微信群消息、口头通知或个人表格代替系统记录。

AI 画像、岗位匹配、评分、面试问题和分析结论均为辅助建议。使用者必须查看证据、置信度和人工确认状态，禁止仅根据 AI 分数自动淘汰候选人。

## 2. 通用操作

### 2.1 登录与权限

- 系统根据 Studio 可信登录身份加载角色、页面权限、操作权限和数据范围。
- 看不到某页面通常是角色未授权；看得到页面但无数据，可能是部门、事业部或面试分配范围限制。
- 电话、邮箱、微信、薪资、简历原文等字段会按角色脱敏。
- 需要查看敏感字段时发起限时解锁申请，审批通过后仅在有效期内可见。
- 不要共享账号、截图传播完整联系方式或把导出文件转发给无权限人员。

### 2.2 页面状态

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 加载中 | 正在读取真实接口 | 等待，不重复提交 |
| 暂无数据 | 当前筛选和权限范围内没有记录 | 清除筛选或创建业务记录 |
| 无权限 | 当前角色无页面或操作权限 | 联系管理员授权，不绕过接口 |
| 服务降级 | 后端已启动但数据库或外部能力未就绪 | 查看健康状态并联系管理员 |
| 同步失败 | 本地记录已保存，外部系统未确认 | 查看错误后人工重试 |
| 待人工确认 | AI 或系统已生成建议，但尚未由负责人确认 | 查看证据并做人工决定 |

### 2.3 搜索、筛选和批量操作

- 人才库支持关键词、适合岗位、阶段、来源、评级、负责人和重复状态等筛选。
- 切换筛选时系统回到第一页；翻页后会清空跨页选择，避免误批量操作。
- 批量推进、分配负责人或加标签前先核对选中人数和目标条件。
- 高风险操作需要原因和二次确认；失败项会单独显示，不应整批重复提交。

## 3. 管理员

管理员负责系统配置、安全、组织和故障处理，不应代替业务负责人做候选人评价。

### 3.1 首次配置顺序

1. 在“设置”中建立事业部和部门，并维护上下级关系及负责人。
2. 新增系统用户，填写用户 ID、姓名、所属事业部、部门和企业微信用户 ID。
3. 为用户分配角色，设置生效时间、到期时间、数据范围和授权原因。
4. 核对系统角色模板：管理员、总经办 HR、招聘专员、HRBP、部门负责人、面试官、员工关系、AI 运营、普通员工。
5. 检查 `/api/access/me` 是否识别当前可信身份；正式上线前将权限模式切换为 strict。
6. 检查数据库健康状态是否为 86/86 ready。
7. 检查企业微信、对象存储、OCR、LLM 和 Owner 通知的真实连接状态。

### 3.2 角色授权

1. 打开“设置 → 组织、角色与隐私权限”。
2. 选择用户和角色。
3. 填写事业部、部门范围、有效期和授权原因。
4. 提交后用该用户身份验证菜单、接口和数据范围。
5. 调岗、离职或临时任务结束时立即撤销授权。

重复授权、过期授权和已撤销授权不会生效。生产环境不得启用开发身份头。

### 3.3 敏感字段审批

1. 查看待审批申请的申请人、候选人、字段、业务原因和申请时间。
2. 判断是否满足最小必要原则。
3. 通过时设置 1–24 小时有效期；不需要的字段应从申请中移除或驳回。
4. 到期后系统自动恢复原脱敏策略。
5. 审批、读取和导出行为均进入安全审计。

### 3.4 日常巡检

- 数据库健康 86/86。
- 最近后端请求无 OSS `NoSuchKey`、持续 5xx 或 401。
- 企业微信连接状态不把错误文本误判为已连接。
- 失败的消息、会议室同步和后台任务有负责人处理。
- 逾期待办、阶段 SLA、重复人才和无负责人需求有明确归属。
- 发布前完成备份、构建、契约测试和浏览器回归。

## 4. HR / 招聘专员 / HRBP

### 4.1 招聘需求

1. 进入“招聘需求”，填写岗位、部门、招聘人数、用工类型、薪资范围、优先级、到岗日期和完整 JD。
2. 保存草稿后检查信息，再提交审批。
3. 按部门负责人、HR 复核和高管终审流程跟进。
4. 审批通过后创建关联职位，配置招聘渠道和 RPA 采集任务。
5. 关闭需求必须填写原因；需求人数和实际到岗由系统回写分析。

### 4.2 收简历与人才入库

1. 可通过上传简历、公开 API、内推二维码或 RPA 采集进入统一人才库。
2. 上传后查看后台解析任务，不要在任务运行中重复上传同一文件。
3. 核对姓名、联系方式、出生年份、教育、经历、技能和求职意向。
4. 查看 AI 画像、能力评分、岗位匹配、证据和置信度，完成或请求人工确认。
5. 处理系统发现的重复案件，确认主档和字段来源后再合并；误合并使用撤销功能。

### 4.3 负责人审查与意向沟通

1. 从“待审查”队列分配或领取人才。
2. 负责人选择通过、保留或不推进，并填写证据和原因。
3. 沟通前可申请联系锁，避免多人同时联系同一候选人。
4. 使用沟通模板记录渠道、结果、候选人意向、微信号和下一次跟进时间。
5. 不允许只在个人微信沟通而不回写系统。

### 4.4 约面与通知

1. 选择候选人、轮次、面试官、时间、形式和会议室。
2. 系统检查面试官和会议室时间冲突。
3. 预约成功后先预览候选人通知，再人工确认发送。
4. 企微同步失败时本地预约仍保留，但必须处理“同步失败”并人工重试。
5. 改期或取消要填写原因，确保候选人、面试官和会议室状态一致。

### 4.5 Offer、背调与入职

1. 创建 Offer 时核对岗位、薪酬、入职日期和审批链。
2. 审批完成后生成文件和安全答复链接；未确认发送不得标记已发送。
3. 候选人的接受、拒绝和协商均保存日期、备注和历史版本。
4. 背调必须先获得候选人授权，再录入核验信息和报告，由人工确认结论。
5. Offer 接受和背调完成后创建待入职单，跟进资料、设备、账号、培训和到岗。

## 5. 部门负责人

### 5.1 审批招聘需求

- 核对岗位必要性、人数、预算、优先级、到岗时间和 JD。
- 通过或驳回必须填写业务意见。
- 只处理本部门或被授权范围内的需求。

### 5.2 审查人才

- 查看人才经历、技能、AI 岗位匹配证据和风险提示。
- 给出通过、保留或不推进意见，并说明与岗位要求的对应关系。
- AI 分数只是参考，不以年龄、性别、婚育、地域等无关因素作决定。
- 需要联系方式时按流程申请，不通过截图或导出绕开脱敏。

### 5.3 面试与最终决策

- 选择适合轮次和岗位的面试官。
- 查看各面试官独立评价和意见分歧，不要求面试官互相覆盖结论。
- 最终推进、Offer 或淘汰决定必须有证据和人工确认。
- 关注本部门需求 SLA、HC 达成、Offer 接受率和入职质量。

## 6. 面试官

### 6.1 维护可用时间

- 维护可面岗位、轮次、时区、每日最大场次和可用时间。
- 临时不可用应及时更新，避免预约后反复改期。

### 6.2 面试前

1. 在“我的面试”查看候选人、岗位、轮次、时间和形式。
2. 只查看完成本次面试所需的最小信息；联系方式默认隐藏。
3. 查看结构化面试模板、测评结果和建议问题。
4. 社招可参考岗位问题分析和薪酬区间，应届生使用结构化清单。

### 6.3 面试中与提交评价

1. 按统一维度记录证据：专业能力、业务能力、逻辑能力、管理/带队能力、沟通协作、动机与价值观等。
2. 分数必须对应事实或候选人回答，不写空泛结论。
3. AI 可生成评价草稿，但面试官必须修改并人工确认。
4. 每位面试官独立提交，提交后锁定，不能覆盖他人评价。
5. 如需纠正，走补充说明或管理员审计流程，不删除原评价。

### 6.4 面试边界

- 不询问与岗位无关的隐私和歧视性问题。
- 不在企业微信群发送候选人完整手机号、身份证、薪酬、背调或内部评价。
- 不向候选人承诺未审批的薪酬、职级、Offer 或入职日期。

## 7. 普通用户与内推人

- 普通用户仅使用被授权页面和数据。
- 内推人通过有效二维码上传简历，填写本人身份、部门、候选人关系和授权说明。
- 系统会自动解析和去重；重复简历不会重复创建独立人才。
- 内推人只查看允许公开的进度，不查看面试评价、薪酬、背调和其他敏感信息。
- 奖励资格以系统规则、候选人有效性和实际入职/在职节点为准。

## 8. 消息和企业微信

1. 先选择模板或填写内容并生成预览。
2. 企业微信群消息会自动隐藏手机号、邮箱、微信号、身份证、薪酬、背调和内部评价。
3. 核对群成员范围、候选人、链接和内容后再次确认发送。
4. 只有收到明确外部成功响应才显示“已发送”。
5. 失败消息显示错误并允许重试；已发送消息不能重复发送。
6. 企业微信连接显示 `850003` 时，由机器人创建者重新授权通讯录权限。

## 9. 数据分析

- 招聘需求和 HC：关注需求人数、到岗、剩余 HC 和完成率。
- 招聘漏斗：按阶段查看转化率和停留时长。
- 渠道分析：区分简历量、有效率、面试率、Offer 率和入职率。
- AI 质量：比较匹配分与真实面试/入职结果，不把相关性当因果。
- 面试质量：样本未成熟时系统应显示数据不足，不强行给排名。
- 导出前核对数据范围；导出文件带用户、时间、请求 ID 水印并进入审计。

## 10. 常见问题

### 页面能打开，但没有数据

先清除筛选，再确认部门、事业部、负责人或面试分配范围。仍为空时联系管理员检查角色授权。

### 联系方式显示星号

这是角色脱敏策略。确有业务需要时发起限时敏感字段申请，不要求管理员永久放开。

### 简历解析失败

确认格式和大小，查看任务错误。原文件会保留，可在问题修复后重试；不要反复上传形成重复任务。

### 企业微信显示连接失败

按页面错误码处理。未绑定由应用主人到 MCP 市场绑定；`850003` 由机器人创建者重新授权企业微信通讯录。

### 预约已保存但企微未同步

本地预约仍有效但不能视为外部预约成功。处理同步错误并重试，必要时人工通知候选人和面试官。

### 系统提示服务降级

停止高风险写入，联系管理员查看 `/api/health/database`。不要通过刷新或重复提交掩盖 503。

## 11. 最小日常闭环

每位业务使用者每天至少完成：

1. 清理本人逾期待办和待跟进人才。
2. 补全当天沟通、面试、Offer 和候选人答复记录。
3. 处理失败消息、同步任务和重复人才案件。
4. 检查明日面试、会议室和面试官安排。
5. 确保所有阶段变化有原因、证据、操作人和时间。
