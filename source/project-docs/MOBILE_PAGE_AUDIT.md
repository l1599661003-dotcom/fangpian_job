# 手机端页面与操作验收清单

本次沿用底部导航的 App 结构，补齐页面内部操作。断点为 760px；桌面不启用手机专属导航、填写目录和扩大输入区。没有增加外部接口、修改权限、修改数据库字段或更换招聘流程。

## 交互约束

- 填写目录只滚动和聚焦原字段，不复制控件、不自动提交，不改变表单提交参数。
- 必填计数使用现有 `required`；测评使用原有 `data-required`。不自行增加业务必填条件。
- 普通长表单不折叠实际字段，以免隐藏浏览器校验目标；目录可收起。AI 解析后仍需人工核对。
- 未提交保护仅在手机浏览器支持 `beforeunload` 时提示关闭 / 刷新风险，不保存个人信息到浏览器存储。它不承诺移动系统强退时保留数据，也不拦截所有应用内跳转。面试评价、测评继续使用其原有自动保存逻辑。
- “展开输入区”扩大原输入框，不创建副本，收起后文字保持不变。
- 危险操作与普通操作保持区别；提交失败不会把错误伪装为成功。
- 招聘官网、会议室两个历史原型仍保留原先示例数据 / 接口边界。这次没有将原型伪装成生产投递或真实会议室预约。

## 复验命令与边界

```sh
npm run build
node --test tests/*.test.mjs
RF_CAPTURE_RESPONSIVE=1 playwright test -c playwright.config.mjs
```

浏览器测试使用独立静态测试服务及模拟 API，不触碰真实人才、不会发出企微消息或预订会议室。外部表单截图位于 `test-results/mobile-journeys-*`，后台各页截图为 `test-results/responsive-*.png`。构建 / 回归不代表已发布，也不能替代真实 iOS / Android 键盘、企业微信内置浏览器和生产送达验收。
