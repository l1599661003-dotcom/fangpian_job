## 4. 技术适配

- 根目录新增 `package.json`，提供可返回的 `build` 和单进程长驻 `start:dev`。
- `pnpm run build` 将原页面和全部运行素材构建到 `dist/client/`。
- `start:dev` 直接执行 `node --watch server.mjs`，不递归委派子包，不启动多个端口。
- 服务监听 `process.env.PORT`，同一端口提供全部页面和静态数据。
- 原 Docker、nginx 或外部部署假设未作为 Studio 运行依赖。
- 没有把原项目数据迁移到 Teable；原交付本身没有服务端数据库，当前继续使用随包静态/Excel 数据。

## 6. 接下来待开发项目清单

下列项目不是本次还原遗漏，而是原交付文件中已经规划、但源码中尚未形成生产后端的能力。

### P0：生产上线阻断项

1. 真实身份、组织与权限
   - 接入 ARP SSO、组织架构、账号、角色模板和数据范围。
   - 将当前前端角色切换改为服务端授权。
   - 实现字段脱敏、导出权限和全局搜索边界。

2. 持久化业务数据库与 API
   - 为招聘需求、职位、候选人、简历、人才库、面试、Offer、入职、内推奖励、通知和日志建立正式数据模型。
   - 把当前静态数组、Excel 加载和页面内存修改改为后端 CRUD、事务和并发控制。
   - 设计文件存储、病毒检测、访问签名、数据备份和恢复。

3. 招聘需求和 Offer 审批流
   - 需求：发起、业务初审、HRBP 复核、总经办 HR 终审、条件式高管终审。
   - Offer：编辑、业务复核、总经办审核、条件式高管终审。
   - 实现驳回、撤回、加签、超时提醒、状态回写和幂等。

4. 职位发布与渠道回流
   - 将审批通过的需求生成正式职位。
   - 接通招聘官网、内推、校招、社群、猎头等渠道发布与下线。
   - 将渠道投递自动回流统一简历库，并记录来源与归属。

5. 候选人官网完整投递链路
   - 职位详情、真实立即投递、附件上传、隐私授权和重复投递校验。
   - 手机号/邮箱验证码和候选人本人身份校验。
   - 投递列表、流程状态、资料补充、面试确认、Offer 签署和入职中心。
   - 当前官网的岗位、验证码和进度均为原型模拟数据。

6. 简历解析与 AI 初筛
   - 接入简历解析 Skill，保留原文、结构化结果、人工修订和版本记录。
   - 实现岗位匹配分、硬性/加分/风险标签和低分待复核机制。
   - 不允许 AI 直接自动淘汰候选人；需提供人工复核和审计。

7. 面试全链路
   - 面试邀约、候选人确认、面试官日历、签到、视频会议和改期/取消。
   - 面试评价 Skill、评价催办、超时升级、不同轮次结论流转。
   - 面试官认证与后续 90 天留存准确率口径。

8. Offer、电子签与入职
   - Offer 模板、薪资结构、异常带宽审批、电子签、撤销和重签。
   - 入职资料采集、证件与附件、工位/设备/账号/宿舍任务。
   - 到岗确认后归档员工主数据并推送商学院课程。

9. 通知、待办和审计
   - 站内消息、应用主人通知、短信/邮件/企微通知策略。
   - 需求、面试、Offer、入职的超时提醒和升级机制。
   - 查看、导出、审批、字段变更、Offer 修改等不可抵赖审计日志。

10. 官网 CMS
    - 首页、专题、SEO、FAQ、员工故事和福利内容配置。

## 7. 推荐开发顺序

1. 先定数据模型、身份权限和文件存储。
2. 打通“需求审批 → 职位发布 → 投递入库 → 面试 → Offer → 入职”主链路。
3. 再接通知、审计、企微会议室、电子签和主平台/商学院联动。
4. 主链路数据稳定后建设 BI 和 AI 复盘，避免 AI 基于演示或不完整数据输出结论。
5. 最后开发推荐算法、智能问答、移动端和高级自动化。
